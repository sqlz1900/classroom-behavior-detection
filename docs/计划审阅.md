# 开发计划审阅意见（审阅轮）

> 审阅对象：docs/开发计划.md · 审阅立场：以「一次跑通、少踩坑」为准

## 🔴 必须修正（开发前解决）

1. **数据集是最大风险，不该放在 M5 末端**
   - 问题：没有 5 类标注数据，训练模块就是空中楼阁；计划里它排在最后，若数据迟迟不到位，整条链路卡死。
   - 修正：M2 阶段同步开始下载公开数据集（Roboflow classroom/behavior 类）；冷启动演示模式（COCO person 映射）**从第一天就作为默认模型**，训练模块只做「数据到位后重训替换」，链路永不阻塞。

2. **预警「持续 ≥ N 帧」去抖状态存内存，Flask 重启即丢，且回调失败无补偿**
   - 修正：a) 去抖参数（帧数/阈值）从 sys_config 读取，支持前端调参；b) 回调失败重试 3 次（指数退避）；c) Flask 本地也落一份 JSONL 日志兜底，SpringBoot 重启期间丢的回调可人工补录。

3. **SpringBoot 转发 MJPEG 流容易踩坑**（默认 RestClient 会把整个流缓冲在内存）
   - 修正：实时流这一条路径前端直连 Flask（:5002），不走 8080；其余 API 统一走 SpringBoot。计划里的「前端不直连 Flask」改为「除 MJPEG 流外不直连」。

## 🟡 建议修正

4. **视频检测的输出等待问题**：一个 5 分钟视频逐帧推理约需 1-3 分钟，同步接口会超时。
   - 修正：改异步任务制 —— `POST /detect/video` 立即返回 taskId，`GET /detect/video/status/<taskId>` 轮询进度，完成后取结果。任务表存内存 dict 即可（单机演示）。

5. **数据库缺索引设计**：detection_record 按时间查询频繁，必须 `INDEX(created_at)`；alert_event 同理。写入 schema.sql。

6. **标注图路径约定不明**：统一 `static/annotated/{yyyy-mm}/{uuid}.jpg`，DB 存相对路径，由 Flask 提供静态访问，避免 SpringBoot 拼绝对路径。

7. **Python 3.13 主环境不要动**：所有依赖装进独立 conda env `yolo11`（3.10），requirements.txt 锁版本。避免污染全局、避免 3.13 下 torch/ultralytics 兼容性踩坑（计划已隐含，此处明确为硬约束）。
